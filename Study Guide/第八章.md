## 8.1 软件测试概述（Overview of Software Testing）

**定义：**
> 软件测试是验证系统是否满足需求并发现潜在缺陷的过程。

**主要目标：**

1. 发现错误（Error Detection）  
2. 验证需求（Requirement Verification）  
3. 评估质量（Quality Assessment）  

📘 **测试层次：**
- 单元测试 → 集成测试 → 系统测试 → 验收测试
(Unit) (Integration) (System) (Acceptance)

---

## 8.2 集成测试（Integration Testing）

在单元测试完成后，对模块之间的交互进行测试，以发现接口错误和逻辑缺陷。

### 8.2.1 目标（Objectives）

- 验证模块间接口正确性  
- 检查数据流和控制流  
- 评估系统功能组合后的行为  

---

### 8.2.2 集成策略（Integration Strategies）

#### 1️⃣ 自顶向下集成（Top-Down Integration）

**特点：**
- 从系统的顶层模块开始，逐步集成下层模块。  
- 未完成的模块由“桩模块（Stubs）”替代。  

**优点：**
- 早期验证系统架构  
- 缺陷定位容易  

**缺点：**
- 需编写大量桩模块  
- 底层功能测试较晚  

📘 **示意图：**
- Main Module
├─ Stub A
├─ Stub B
└─ Stub C

---

#### 2️⃣ 自底向上集成（Bottom-Up Integration）

**特点：**
- 从底层模块开始测试，再逐步向上集成。  
- 使用“驱动模块（Drivers）”模拟上层调用。  

**优点：**
- 底层逻辑验证早  
- 不需要桩模块  

**缺点：**
- 系统功能验证较晚  

📘 **示意图：**
- Lowest Level Modules → Combine into Subsystems → Full System

---

#### 3️⃣ 混合集成（Sandwich / Hybrid Integration）

结合前两种策略：
- 上层模块采用自顶向下集成  
- 下层模块采用自底向上集成  
- 中间层同时进行合并测试  

**优点：**
- 灵活高效  
- 适合中大型项目  

---

### 8.2.3 增量集成（Incremental Integration）

每次仅加入一个或几个模块进行测试，逐步扩展系统范围。  
相比“一次性集成（Big-Bang Integration）”，风险更小、定位更容易。

---

## 8.3 系统测试（System Testing）

**定义：**  
对整个集成系统进行全面测试，验证其功能、性能、安全性及兼容性。

### 8.3.1 功能测试（Functional Testing）

验证软件是否满足功能需求说明（SRS）。  
常见方法：  
- 黑盒测试（Black Box Testing）  
- 等价类划分（Equivalence Partitioning）  
- 边界值分析（Boundary Value Analysis）

---

### 8.3.2 性能测试（Performance Testing）

测试系统在不同负载下的响应时间与吞吐量。  
包括：

- 压力测试（Stress Testing）  
- 负载测试（Load Testing）  
- 稳定性测试（Stability Testing）  

---

### 8.3.3 安全性与可靠性测试（Security & Reliability Testing）

**安全测试：**  
防止未经授权的访问与数据泄露。  

**可靠性测试：**  
验证系统在长期运行下的稳定性与容错能力。  

---

### 8.3.4 可用性与兼容性测试（Usability & Compatibility Testing）

- **可用性测试**：评估界面友好度与用户体验。  
- **兼容性测试**：验证系统在不同平台、浏览器、硬件下能否正常运行。  

---

### 8.3.5 回归测试（Regression Testing）

在修改或修复错误后，重新执行测试，确保旧功能未受影响。  

📘 常见策略：
- 自动化测试脚本（Automated Regression Scripts）  
- 测试用例版本控制（Versioned Test Cases）  

---

### 8.3.6 验收测试（Acceptance Testing）

由客户或最终用户执行，用于确认系统是否可交付。

**类型：**

| 类型 | 说明 |
|------|------|
| Alpha 测试 | 内部环境下用户参与 |
| Beta 测试 | 真实用户环境下测试 |

---

## 8.4 测试自动化与管理（Test Automation and Management）

### 8.4.1 自动化测试工具（Automation Tools）

常见工具：

| 工具 | 语言/平台 | 功能 |
|------|------------|------|
| Selenium | Web | UI 自动化测试 |
| JUnit | Java | 单元与集成测试 |
| pytest | Python | 自动化测试框架 |
| Postman | API | 接口测试 |
| LoadRunner | 多语言 | 性能测试 |

---

### 8.4.2 测试计划与报告（Test Planning & Reporting）

一个完善的测试计划应包含：

- 测试目标（Objectives）  
- 测试范围与优先级（Scope & Priority）  
- 测试环境与工具（Environment & Tools）  
- 测试用例与执行计划（Test Cases & Schedule）  
- 缺陷跟踪与报告机制（Defect Tracking）  

---

## 8.5 小结（Summary）

| 主题 | 要点 |
|------|------|
| 测试层次 | 单元 → 集成 → 系统 → 验收 |
| 集成策略 | 自顶向下、自底向上、混合、增量 |
| 系统测试 | 功能、性能、安全、兼容性 |
| 测试管理 | 自动化与报告体系 |

✅ **测试的目标是发现错误，而不是证明程序“没有错误”。**
